点击灵动岛上的模型，或从菜单栏图标打开主窗口。概览页用来回答一个问题：**某个模型在某个渠道上，最近表现怎么样。**

[返回 README](../../README.md#功能) · [功能索引](README.md)

## 页面结构

| 区域 | 内容 |
|---|---|
| 顶部 | 功能搜索（`⌘K` / `Ctrl+K`）、模型目录同步时间、时间范围选择 |
| 筛选栏 | 模型、渠道、Key 分组、推理档位四个下拉框，显示当前命中的对象数，可清除筛选 |
| 活跃模型 | 当前 Agent 列表（已打开 / 待命），以及每个模型对象的卡片；可点"立即采样" |
| 余额 | 当前渠道余额；各供应商余额列表，接口失败时直接显示错误（如 HTTP 状态码） |
| 核验费用 | 所选模型的总花费、平均单次、最近单次 |
| 实时核心指标 | 核验匹配次数、Cache 命中率、TTFT，以及指标趋势图 |

左侧导航分两组：工作台（概览、模型、路由、Cache、TTFT、模型核验、花费统计）和系统（告警、日志、设置）。

## 四元组：为什么要分开统计

Modivue 把每个监测对象定义为 **模型 × 渠道 × Key 分组 × 推理档位**。同一个模型经过两个中转站调用，或用两组 Key、两个推理档位调用，会成为不同的对象，各自计算指标。这样可以避免把不同路由的表现平均成一个结论。

## 指标怎么算

| 指标 | 计算方式 |
|---|---|
| TTFT | 从请求发出到首个有效文本或工具事件的时间 |
| Cache 命中率 | 只使用提供方明确返回的缓存字段：Chat Completions 读 `usage.prompt_tokens_details.cached_tokens`，Responses 读 `usage.input_tokens_details.cached_tokens`，Anthropic Messages 读 `usage.cache_read_input_tokens` |
| 模型核验 | 所选核验方法在时间窗口内的匹配数与有效比对数，详见 [模型核验](verification.md) |
| 余额 | 读取供应商余额接口，详见 [费用与余额](cost.md) |

指标缺失时显示缺失状态，不用 0 代替。所有请求都保留原始 JSON。

## 模型名称

模型目录来自 [Models.dev](https://models.dev/catalog.json)，每 6 小时检查一次更新。下载或解析失败时保留上次成功的目录，并标记为陈旧。规范模型 ID、渠道返回的原始模型名和模糊匹配证据分别保存。

## 搜索

按 `⌘K` / `Ctrl+K` 打开搜索：上下键选择，Enter 跳转，Escape 关闭。结果分页显示，打开搜索时弹窗和背景都不会滚动。
