# 工程原则

根据[用户指定的工程规范](https://blog.52013120.xyz/tools/skills/SKILL.html)整理。项目约束以根目录 `AGENTS.md` 为准。

- 用最少的必要代码完成真实使用流程。保持逻辑清晰、架构简单、职责明确。
- 一个问题保留一个实现。减少依赖、重复状态、重复函数和无意义包装。
- 先读当前源码、调用链和执行逻辑，再作结论。结论对应实际位置。
- 修复缺陷时，定位并验证根因，再修改。不要用猜测、补丁层或防御性代码掩盖原因。
- 采用第三方库前，检查所用版本的文档、公开 API 和相关实现。
- 只处理当前需求和真实问题，不为假设场景增加代码。
- 在当前变更范围内清理已被替代的实现和无用依赖。不要扩展到无关模块。
- UI 使用统一的组件、术语和间距。控件符合平台惯例，操作流程完整。
- 说明选定方案、原因、取舍和影响。删除无法支持决策的空泛内容。

禁止在用户未主动要求时生成任何测试代码。表达使用清晰的简体中文，不机械套用英语词汇或句长规则。
